# 两轮交互评测 / Interaction review

Date: 2026-09-20. Baseline: `8afe8d7`.

## 方法与边界

这是维护代理的启发式评测，不是独立人类可用性研究。使用 Computer Use 在实际 Chrome 中操作，结合截图、可访问性树、只读 DOM 尺寸测量和离线回归测试。

测试服务：隔离端口 4174、仓库内置虚构示例、空模型密钥。未使用真实聊天、未调用付费模型、未读取用户主工作空间的浏览器存储。首次探测主服务不可连接，随后启用隔离测试服务。

保留四类、群选择、手动分类、待办队列和模型确认流程。遵循参考项目 Jev Ultrafast 的「具体任务 → 实际动作 → 可验证结果」方式，不复制性能数字，不把模型外观或动画当作成功。

## 第一轮：功能与反馈

| 操作 | 复现的问题 | 修复与复测 |
| --- | --- | --- |
| 加入待办 → 从队列打开详情 → 改为我的待办 | 队列副本改变，看板仍为紧急；再次打开队列显示已改，说明状态分裂 | 详情优先绑定原消息，手动分类同步保存至原消息与队列；浏览器确认紧急 2→1、待办 3→4 |
| 选择飞书 → 留空搜索 → 点击搜索 | 错误显示在模态弹窗后面，弹窗内容无反馈 | 就地显示 role=alert；空输入在本地校验，无需平台请求 |
| 看搜索弹窗 | 输入框把「搜索群聊」按钮挤成两行 | 输入可收缩，按钮不收缩不换行；390px 截图确认 |
| 对照卡片与详情时间 | 同一消息卡片显示上海时间，详情显示浏览器本地时间 | 两者统一使用浏览器本地时区 |

补充代码检查发现异步请求期间可修改来源与条数，可能混淆请求范围；请求期间锁定可变控件，结束后恢复原禁用状态。用受控异步 DOM 测试验证，不声称做了真实模型请求。

## 第二轮：阅读与连续操作

| 操作 | 复现的问题 | 修复与复测 |
| --- | --- | --- |
| 键盘空格勾选待办 | 列表重绘后焦点退回页面，不能继续空格撤销 | 按消息/队列身份恢复控件焦点与滚动位置；真实浏览器连续空格完成/撤销均保持焦点 |
| 桌面截图检查卡片 | 正文和加入待办按钮争抢横向宽度，正文被迫窄排 | 卡片改为内部网格，正文完整占用第二列，操作独立行；1156px 视口下卡片宽 224.5px，正文宽 176.5px |
| 实际拖动第二项到第一项，随后刷新 | 检查已有拖动功能是否可靠 | 顺序与完成状态刷新后保留 |
| 390px 窄屏主页面及搜索弹窗 | 检查响应式可用性 | 无横向溢出，正文宽 285px；按需展开详情，未增加主界面功能 |

关闭按钮补充可访问名称。真实待分类消息的详情不再冒称「预设演示结果」；未分类选择器提供明确占位选项。

## 评价

- **演示主流程：通过。** 能理解四类、加入待办、调整分类、完成并保留状态。
- **反馈与一致性：本轮复现项通过复测。** 弹窗错误可见，队列/原文分类同步，连续键盘操作不失焦。
- **阅读密度：改善。** 无价值栏保持默认折叠，正文截断仅影响预览，完整原文可打开；没有新增导航或统计面板。
- **完整生产可用性：未证明。** 本轮不验证真实平台权限、群搜索结果、Jev 准确率/速度、消息链接在原生客户端中的定位，以及屏幕阅读器完整兼容性。

验证：19 项离线测试通过；浏览器操作与截图已在当前开发会话检查。没有将用户数据或带认证信息的截图提交到仓库。

停止条件已达到：两轮已完成、确定问题已修复、针对性检查通过。后续只对新的可复现问题开启下一轮。
